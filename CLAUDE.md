# esposc: заметки для агента

Что это и как устроено - в `README.md`. Ручки BSP - в `README.md` и `docs/controls.html`.

## Правила проекта

- Разъём **USB** платы никогда не втыкать в ПК. Прошивка и лог только через COM: `/dev/ttyACM0`.
- TDD: хост-тест до кода, увидеть красный, потом зелёный. Тесты в `host/test_*.c`, свой мини-фреймворк `host/test.h`.
- Коммит каждой готовой единицы работы, git-личность `antifreezzz <me@kvatech.ru>`.
- Комментарии и доки по-русски, код и git по-английски, без длинных тире.
- Меняешь ручки, страницы или MIDI - обнови `README.md` (таблица ручек), `docs/controls.html`
  (массивы `PAGES`, `K303`, `MODELS` и тексты карточек) и спеку этапа.
- В рендере (всё, что зовётся из `acid_synth_render*`) никаких локов, аллокаций и логов.

## Как пользователь работает с BSP

- Смотрит на экран BSP: там значение энкодера 0..127. Маппинг должен совпадать с тем, что на экране:
  энкодер 1 значение N = страница N, значения вне диапазона игнорируются. Зоны хода и листание
  по направлению пользователь отверг.
- Щелчки энкодеров BSP чёткие, по 1 значению; при быстром вращении BSP пропускает значения (шаг 4 и больше).
- BSP помнит положение энкодеров между включениями.

## Команды

```sh
# хост-тесты
cmake -S host -B host/build && cmake --build host/build && ctest --test-dir host/build
# прошивка
. ~/esp/esp-idf-v6.1/export.sh && idf.py -p /dev/ttyACM0 flash
# образ тарелок (раздел samples, idf.py flash его не трогает; сборка - в README)
esptool.py --chip esp32s3 -p /dev/ttyACM0 write_flash 0x210000 cymbals.bin
# тесты сборщика образа
python3 -m unittest discover -s tools/samples
```

Лог без `idf.py monitor` (ему нужен tty): pyserial, `serial.Serial('/dev/ttyACM0', 115200)`,
читать строки в файл в фоне. Открытие порта может перезагрузить плату.

## Инварианты и как их проверять

- **Демо-трек бит в бит как в `main`** при любых правках, которые не должны менять звук:
  ```sh
  git worktree add /tmp/esposc-main main
  cmake -S /tmp/esposc-main/host -B /tmp/esposc-main/host/build && cmake --build /tmp/esposc-main/host/build
  /tmp/esposc-main/host/build/acid_render /tmp/a.wav 180 && host/build/acid_render /tmp/b.wav 180
  cmp /tmp/a.wav /tmp/b.wav && git worktree remove --force /tmp/esposc-main
  ```
  Демо (`acid_demo_song.c`) - смоук-тест: шлёт MIDI как BSP. Меняешь ручки или поведение - проверь, что
  `host/test_demo_smoke` по-прежнему видит каждую фичу; новая фича - добавь её в песню и в тест охвата.
- Бюджет: блок 2000 мкс, кусок 666 мкс. Ядро 1: синт 1, ударка, смесь и эффекты; ядро 0: тарелки и перкуссия
  того же куска, потом синт 2 на кусок вперёд. Худший случай - стресс-песня `acid_stress_song.c` (оба синта modal,
  все эффекты, тарелки на +12, дробь перкуссии на модальной модели), на ней ядро 1 ~1430 мкс из 2000 в среднем,
  ядро 0 ~380 из 666 на кусок. Перегруз блока лавинный (underrun -> USB грузит ядро 0 -> стопор в десятки мс):
  новое в рендере мерить на плате стендом, не только на ПК (тарелки на ПК стоили копейки, на плате - нет):
  ```sh
  idf.py -B build-stress -DESPOSC_STRESS=1 -p /dev/ttyACM0 flash   # стенд: стресс-песня, защита выключена
  ```
  В логе раз в 10 с среднее и худшее по ядрам и разбивка ядра 1 по участкам (`acid_prof.h`). После замеров
  прошить обычную сборку (`idf.py flash`). Защита от лавины - `acid_synth_set_load` (перкуссия и тарелки на один голос).
- Демо бит в бит - только для правок, которые не трогают арифметику. Замена деления или libm быстрой формулой
  меняет младшие биты: тогда сравнивать уровнем разницы (numpy, rms разницы ниже -100 дБFS) и держать тест,
  который прибивает новую формулу к старой.
- Blob памяти ручек версионирован магией `BLOB_MAGIC` в `acid_synth.c`: меняешь раскладку
  `knob[][]` или число типов - подними версию, иначе старый blob из NVS применится криво.

## Грабли

- Plaits собирается с `-DTEST` (переносимый режим без ARM asm) и `-include stdio.h`; предупреждения вендорного кода глушатся `-w`.
- `git checkout <файл>` для отката мутации в тесте стирает и все незакоммиченные правки файла.
  Мутации откатывать точечно (sed, Edit) или сначала коммитить.
- Snap-chromium не пишет в `/tmp`: скриншот `--headless --screenshot=$HOME/x.png`, потом перенести.
- `idf.py` после правок `sdkconfig.defaults` их не подхватывает, если `sdkconfig` уже есть: править и его (он в .gitignore).
- В горячем цикле рендера на плате не звать libm (`tanf`, `exp2f`, `floorf`, `powf`, `sinf`): из флэша они стоили
  перкуссии в 5 раз больше всего остального голоса. Быстрые замены - в `acid_math.h` (`acid_exp2`, `acid_tan`,
  `acid_sin2pi`, `acid_tanh`, `acid_rcp`).
- И не делить float на каждом сэмпле: у FPU S3 нет деления, GCC при любых флагах зовёт программный `__divsf3`
  (~46 тактов). Коэффициенты считать при смене ручки, `1/sr` заранее, иначе `acid_rcp` из `acid_math.h`.
  Рендер упирается в вычисления, не в кэш команд: QIO и вынос modal в IRAM дали ноль (замер 2026-10-30).
- `tools/samples` (сборщик образа и его тесты) - системный `/usr/bin/python3` с numpy. После `export.sh` ESP-IDF
  `python3` - его venv без numpy: тесты падают на импорте. Запускать в отдельной оболочке или `/usr/bin/python3`.
