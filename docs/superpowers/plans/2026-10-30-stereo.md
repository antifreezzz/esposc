# Stereo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** стерео-выход: панорама синтов и ударки, пинг-понг и случайная панорама повторов дилэя, стерео-эффекты, буферы в PSRAM.

**Architecture:** рендер отдаёт два плоских буфера L/R (`acid_synth_render_lr`), старый моно `acid_synth_render` остаётся
обёрткой `0.5f * (l + r)` (для автопилота L == R, обёртка точна бит в бит) - хост-тесты не переписываются.
Буферы дилэя и статтера - указатели, память один раз из `acid_mem_big` (на плате PSRAM, на хосте calloc).

**Tech Stack:** C11, ESP-IDF v6.1, хост-тесты `host/test.h`.

**Spec:** `docs/superpowers/specs/2026-10-30-stereo-design.md`

## Global Constraints

- Комментарии по-русски, код и git по-английски, без длинных тире. TDD: красный, потом зелёный.
- Панорама 0 слева, 64 центр, 127 справа; в центре оба канала 1; влево правый `v/64`, вправо левый `(127-v)/63`.
- Умолчания: синты 64, хэты 80, клэп 48, малый 64, движение 0, ширина 127. Панорамы только в live.
- Энкодер 11 страницы 4 (slot 10): движение 0/1/2, остальное игнор. Энкодер 12 (slot 11): ширина 0..127.
- Микс slot 13/14 (энкодеры 14/15) - панорама синтов; ударка slot 13/14/15 (энкодеры 14-16) - хэты, клэп, малый.
- Автопилот бит в бит как в `main` (`acid_render` + `cmp`). Без локов, аллокаций, логов в рендере и MIDI.
- Худший рендер на стенде не выше ~1800 мкс из 2000.

## Review Focus

1. Смена движения 1 -> 0 и 0 -> 1 при звучащих повторах: без скачка (тест на максимум разности соседних сэмплов).
2. Случайная точка на шве сетки повторов: плавный переход ~5 мс, без щелчка.
3. Автопилот после переезда на `render_lr`: `acid_render` пишет тот же файл (`cmp`).
4. Сохранение ручек во flash при игре с включённой PSRAM: прошивка не падает (проверка на плате).
5. Live без поворотов ручек: синты в центре дают L == R, звук не тише и не громче прежнего.

### Task 5: Delay motion

**Files:** `acid_fx.h/.c`, `acid_synth.c`, `host/test_fx.c`, `host/test_live.c`.

**Produces:**
```c
void acid_delay_set_motion(acid_delay_t *d, int motion, int width); // motion > 2 игнор, width 0..127
void acid_delay_next2(acid_delay_t *d, float in, float *l, float *r); // повторы в два канала
```
Алгоритм (тесты его не определяют целиком): `m` плывёт к 1 в пинг-понге и к 0 иначе за 240 сэмплов.
`A_in = in + fb * ((1-m)*lpA + m*lpB)`, `B_in = m * fb * lpA`. Панорама A: в центре 64, пинг-понг `64 - w/2`
(на 127 ровно 0), случайно - новая цель на каждые `d` сэмплов; B: `64 + w/2`. Позиции плывут к цели за 240 сэмплов,
усиления через `acid_pan` от дробной позиции. Генератор xorshift. Линия B читается той же задержкой `d`.
`active` - обе линии.

- [ ] Тесты: `test_delay_center_same_as_before` (движение 0: L == R == прежний моно-выход на импульсе);
  `test_delay_pingpong` (fb 0.5, ширина 127, импульс: пик L около T, R там ~0; пик R около 2T, L ~0);
  `test_delay_width_zero` (пинг-понг, ширина 0: L == R); `test_delay_random_within_width` (ширина 64: все точки в 32..96,
  меняются, но не чаще раза в T); `test_delay_motion_switch_smooth` (повторы звучат, движение 0 -> 1 -> 0: максимум
  |x[i]-x[i-1]| не больше, чем без переключения, x 1.5); `test_delay_motion_ignores_3`;
  `test_live_fx_motion_knobs` (страница 4, энкодер 11 = 1, 12 = 100 доходят до дилэя).
- [ ] RED, реализация, GREEN, `cmp`, commit `feat(acid): delay ping-pong and random pan of repeats`.
