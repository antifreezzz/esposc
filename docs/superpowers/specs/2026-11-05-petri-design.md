# Чашка Петри: оптимальный вариант (этап 16)

Исходная полная спека и веб-прототип - у пользователя («Чашка Петри: спецификация для ESP32», прототип
«Звучащая чашка Петри»). Полная версия тяжела даже для браузера, здесь урезанный вариант под наши бюджеты.
Дальше план через writing-plans.

## Зачем

Wave terrain поверх живой реакции Грея-Скотта: панель считает чашку и жителей, по орбите снимает один период
волны в 256 точек и шлёт синту. Синт играет волну как обычный тип слота. Рельеф растёт, делится, ползёт, жители
едят, сеют и крутят его, вместе с ним меняются тембр и фильтр.

## Цели

- Тип слота синта **PETRI** (номер 25) рядом с 303 и Plaits.
- Симуляция и жители на панели, по проводу только таблица и 6 модуляций.
- Без панели синт автономен: тип играет зашитые таблицы.
- Всё крутится с BSP: две страницы ручек, экран чашки на панели с каплей по тапу.

## Не цели (этот этап)

- Два PETRI одновременно со своими орбитами: пользователь их одновременно не запускает. Если тип выбран на обоих
  синтах, оба читают одну таблицу (не запрещено, бюджет терпит).
- PETRI как тип слоя: нельзя (слои на ядре 0, запаса нет).
- Настраиваемая матрица модуляций (выбор источника и цели) - только фиксированные маршруты с глубинами.
- Сохранение состояния чашки: после включения новая чашка с фиксированным seed.

## Что урезано относительно полной спеки

| Полная спека | Здесь | Почему |
|---|---|---|
| 4-й инструмент поверх синтов | тип слота синта | ядро 1 ~1680/2000 мкс, ядро 0 ~448/666: сверху места нет |
| 120x120 float, два набора сеток | 96x96 int16 Q15, обновление на месте с кольцом из 2 строк, экран x5 | внутренняя RAM панели занята LVGL (куча 128 КБ, буферы отрисовки ~92 КБ, bounce ~19 КБ) |
| 0-30 шагов, кадр 50 Гц | 0-8 шагов, 20 кадров/с | шаг float 120x120 на S3 ~5 мс |
| Δk float | int8, шаг 0.012/127 | память |
| Свой ладдер с tanh и exp на сэмпл | `acid_ladder_tick` + штатный перегруз синта | готово, без делений и libm |
| 6 голосов | 4 голоса, один фильтр (парафония) | секвенсоры BSP моно, голоса нужны для хвостов и клавиш |
| Автоусиление с делением на сэмпл | усиление раз в блок через `acid_rcp` | у FPU S3 нет деления |
| Матрица 5 слотов | 5 фиксированных маршрутов, ручки - глубины | без UI матрицы |
| Кнопки +/- жителей | численность каждого типа - ручка | крутится с BSP |
| Пакет 528 байт, свой sync, CRC16 | два кадра `pl_proto` | наш протокол: длина 1 байт, CRC-8, длина фиксирована по типу |
| Пакеты параметров синт -> экран | не нужны | ручки чашки - обычные ручки синта, панель их видит через `PL_KNOB` и снимок |
| Без панели тишина | зашитые таблицы | синт автономен, демо и смоук на ПК |

## Симуляция (панель, `components/petri`)

- Сетка 96x96 на торе, U и V int16 Q15 (1.0 = 32767). Обновление на месте: две строки-кольца хранят старые значения
  строки выше и текущей, сетки второго набора нет. Лапласиан 9 точек (0.2 стороны, 0.05 диагонали, -1 центр),
  Du = 1, Dv = 0.5, dt = 1, формулы как в полной спеке.
- Пресеты (F, k): Митоз 0.0367/0.0649 (по умолчанию), Кораллы 0.0545/0.0620, Лабиринт 0.0290/0.0570,
  Черви 0.0650/0.0630 (исходные 0.078/0.061 гаснут даже во float), Солитоны 0.0300/0.0620, Коньки 0.0620/0.0609. Ручки «тонко» сдвигают F и k от пресета.
- Старт: U = 1, V = 0, 12 капель радиусом 2-5 клеток (U = 0.5, V = 0.25..0.30), ~600 шагов до первого кадра.
  Капля по тапу: радиус 2. Генератор случайных чисел свой, с фиксированным seed (детерминизм для тестов).
- Шагов на кадр 0-8 (по умолчанию 4), кадр 20 Гц. Задача на ядре панели, свободном от LVGL.
- Δk int8 96x96, затухает x0.999 за кадр (на 20 Гц пересчитать: x0.997).

## Жители

Типы и движение как в полной спеке, с переводом радиусов на сетку 96 (x0.8, округлить). Максимумы: пожиратели 16,
сеятели 4, мутагены 4, вихри 3. Стартовый набор: 3, 1, 2, 1. Ручка численности задаёт целевое число: лишних
убирает с конца, недостающих рождает в случайном месте; пожиратели дальше живут своей экологией (деление, гибель,
иммигрант), ручка для них - потолок и стартовое число после пересева. Энергия, теснота, иммигрант (через 100 кадров
на 20 Гц) - как в полной спеке, кадровые константы пересчитать с 60 на 20 кадров/с.

## Рельеф и таблица

- 4 режима рельефа (Высота, Край, Фолд, Пустота), контраст c = 40^x, считаются только в 256 точках орбиты.
- 5 форм орбиты (Круг, Восьмёрка, Лиссажу 3:2, Роза, Эпицикл), радиус 2-48 клеток (по умолчанию 18).
- Центр орбиты: дрейф по эллипсу (скорость ручкой) или следование за первым пожирателем.
- Снятие: билинейное чтение V с переносом через край, формула режима, вычесть среднее, int16 без нормализации
  по пику, поправка громкости по режиму (Край и Пустота x2.5 к Высоте, подобрать на слух).
- Модуляции раз в кадр, int8 ±127 = ±1: pop, dk, vort, energy, jump, dens (формулы полной спеки, 24 точки орбиты).

## Протокол

Таблица 256 x int16 = 512 байт, а нагрузка кадра `pl_proto` - до 255 байт (длина 1 байт). Поэтому четыре кадра
панель -> синт, длина фиксирована по типу:

- `PL_PETRI_0..2`: номер таблицы (1 байт) + 64 точки (128 байт) = 129 байт.
- `PL_PETRI_3`: номер + 64 точки + 6 модуляций int8 + счётчик прыжков + флаги = 137 байт.

Синт собирает таблицу по номеру, применяет только полную (все 4 части с одним номером), иначе доигрывает прежнюю.
Трафик ~11 КБ/с при 20 Гц, линия 1 Мбод (~100 КБ/с).

Приём - в задаче `main/panel_uart.c` (ядро 0), готовая таблица в двойном буфере с номером, рендер забирает без
локов. Капля по тапу синту не шлётся.

## Голос (синт, `acid_petri`)

- 4 голоса, замена самого старого, случайная начальная фаза. Фаза uint32, индекс - старшие 8 бит.
- Таблицы: A (прежняя), B (новая), frozen. Чтение с линейной интерполяцией, x = A + (B - A) * w, w растёт 0 -> 1
  за 50 мс; новая таблица: B -> A. Фриз: x = live * (1 - m) + frozen * m, m к цели за 30 мс.
- Сглаженные копии (2/4/8 точек) раз на таблицу; выбор копии по высоте ноты (порог около 1 кГц, на слух).
- DC: y = x - x1 + 0.995 * y1 (коэффициент под 48 кГц). Автоусиление по уровню, коэффициент усиления раз в блок.
- Огибающая громкости: атака 1 мс - 2 с, релиз 20 мс - 3 с, коэффициенты при смене ручки.
- Сумма голосов -> `acid_ladder_tick` (коэффициенты на управляющей частоте) -> штатный перегруз синта.
- Огибающая фильтра: скачок до 1 на новой ноте и на прыжке сеятеля, спад 30 мс - 2 с.
- Маршруты (раз в таблицу, сглаживание 15 мс на синте): пожиратели -> срез (±4 октавы), мутаген -> резонанс,
  вихрь + прыжок -> глубина огибающей, сытость -> перегруз (drive, глубина фиксированная 0.5).
- Без связи с панелью (0.5 с без полной таблицы) - зашитые таблицы `acid_petri_tables.c`: 32 таблицы, снятые
  хостом той же симуляцией (`tools/petri_bake`), идут по кругу с кроссфейдом, модуляции - записанные вместе с ними.
- Бюджет: не дороже modal + перегруз (~778 мкс на блок), ожидание ~250. Мерить стендом `build-stress`.

## Ручки

**Синт, тип PETRI** (E2 тип, E14-16 штатный перегруз): E3 срез (60 Гц - 8 кГц), E4 резонанс, E5 глубина огибающей
фильтра, E6 спад огибающей, E7 атака, E8 релиз, E9 режим рельефа (0-3), E10 контраст, E11 форма орбиты (0-4),
E12 радиус, E13 центр: 0-126 скорость дрейфа, 127 - ехать на пожирателе.

**Страница «Чашка»** (штатная, BSP энкодер 1 = 18; номер сверить с `_Static_assert` в `main/panel_uart.c`, порог
«больше 17 игнор» поднять до 18): E2 пресет (0-5), E3 F тонко, E4 k тонко (64 = пресет), E5 шагов на кадр (0-8),
E6 пожиратели, E7 сеятели, E8 мутагены, E9 вихри, E10 аппетит, E11 сила мутагенов, E12 глубина пожиратели -> срез
(64 = 0), E13 глубина мутаген -> резонанс, E14 глубина вихрь и прыжок -> огибающая, E15 фриз (0-63 выкл, 64+ вкл;
каждый переход вверх - переснять), E16 пересеять (переход 0 -> 1).

Ручки страницы «Чашка» синт хранит как обычные и шлёт панели; панель применяет их к симуляции. Сцены и свои
страницы видят их как любые штатные.

## Панель

- Экран чашки: плитка PETRI во втором экране меню (рядом с GRIDS). Сетка своим объектом с `LV_EVENT_DRAW_MAIN`
  (как `ui_grids.c`), палитра LUT 256 из 5 опорных точек полной спеки, масштаб x5, след мутагена поверх. Орбита
  точками, жители простыми фигурами. Тап и ведение пальцем - капля. Шапка - назад, кнопка «ручки» - страница «Чашка».
- Симуляция идёт всегда, пока на каком-то синте тип PETRI (иначе спит), экран открыт или нет.
- Проверить `lv_mem_monitor` после построения экрана и свободную внутреннюю RAM до и после выделения сетки.

## Где код

- `components/petri/` - чистый C, общий для панели и хоста: `petri_sim`, `petri_agents`, `petri_capture`.
- `components/panel_link`: `pl_proto` (кадры `PL_PETRI_0..3`), `pl_labels.c` (подписи PETRI и «Чашка»).
- `components/acid`: `acid_petri.c/.h`, `acid_petri_tables.c`; `acid_synth.c` - тип 25, `ACID_LAYER_OFF` -> 26,
  `BLOB_MAGIC` версия 4, слой не PETRI.
- `main/panel_uart.c` - приём таблицы. `panel/main/` - `petri_task.c`, `ui_petri.c`.
- Доки по правилу CLAUDE.md: README, `docs/controls.html`, `pl_labels.c`.

## Порядок

1. `components/petri` с хост-тестами: Q15 против эталона float (доля V > 0.1 и число пятен близки), детерминизм
   по seed, капли, тор; жители; снятие таблицы и модуляций.
2. Стенд панели: мс на шаг, свободная внутренняя RAM после LVGL. Если шаг дороже 3 мс - снизить потолок шагов.
3. Голос и тип 25 на зашитых таблицах, демо в обеих песнях, `test_demo_smoke`, стенд `build-stress` с PETRI
   на синте 1 вместо modal.
4. Кадры `PL_PETRI_0..3`, переход на живые таблицы и назад.
5. Экран и страница «Чашка» на панели.
6. Доки, подписи, настройка на слух на железе.

## Проверка

- Хост-тесты зелёные.
- Демо бит в бит как в `main` до шага 3, где звук меняется намеренно.
- Стенд: ядро 1 не выше нынешних ~1680 мкс в среднем с PETRI вместо modal; защита не включается в метале.
- Панель: 20 кадров/с с экраном чашки, куча LVGL свободна больше 20 КБ, синт без потерь кадров по CRC.
